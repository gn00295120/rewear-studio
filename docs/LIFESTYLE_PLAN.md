# 生活照建立衣櫃：實作與驗收

使用者需求：一次上傳多張生活照，辨識穿在人身上的衣物，可在合照指定人物，
對不同照片中可能相同的衣物提供合併建議，人工確認後保留所有來源。

## 實作範圍

- [x] 批次照片／影片：最多 32 檔、每檔 50 MB、整批 256 MB；個別無效檔不影響其他檔。
  批次與個別進度保存到 SQLite，提供整批取消、失敗項目重試；重試保留原分析。
  相同 client_id 重送不建立重複任務，佇列容量不足時明確拒絕而非漏檔。
- [x] 生活穿搭模式：使用 SAM 分割可見衣物，再判斷類別與品質。可辨識但局部遮擋的
  穿搭結果列為「穿搭待確認」，保留可見屬性；碎片、模糊及非衣物不能自動收錄。
- [x] 逐張框選人物：可用滑鼠／觸控及鍵盤調整區域，座標依照片正規化方向保存。
  對選區進行衣物分割，保留完整原圖與選區，不以臉部辨識推斷身份。
- [x] 相似衣物建議：跨照片比較可見類別、顏色、圖案與本機影像特徵，明確標為相似
  候選而非同件結論；只有人工確認才合併，已分組成員不重複建議。
- [x] 可取消合併：同一件衣物包含多筆來源，主紀錄由使用者選擇；不刪除照片、
  原分析、人工編輯或稽核紀錄。清單顯示獨立衣物，匯出保留全部來源及分組資訊。
- [x] 相容性：既有上傳、取消重試、品質判定、編輯、搜尋、影片、匯出持續可用。
  更新資料結構前備份；既有正式 14 筆分析結果不作測試或重新判讀。
- [x] 驗證：隔離 API／資料庫、真實編碼器、桌面／手機／鍵盤瀏覽器、公開授權
  真人穿搭照片與真實模型。記錄失敗和模型差異，不把模擬模型當成辨識準確率。

## 介面與資料契約

- POST `/api/batches`：multipart `files`、`provider`、`mode`、`concept`、
  `selections`（每檔 null 或 [left,top,right,bottom]，正規化 0..1）、`client_id`。
- GET `/api/batches`、GET `/api/batches/{id}`：保存批次、工作清單、逐檔錯誤及彙總進度。
- POST `/api/batches/{id}/cancel`、POST `/api/batches/{id}/retry`：取消未完成工作；
  重試建立新批次，僅含 failed／partial／cancelled 工作。
- `mode=outfit` 只適用照片；`person_box` 可傳入單檔上傳。
- quality `needs_confirmation` 是可讀的穿搭片段，與 `needs_retake`／`unassessed` 分開。
- GET `/api/duplicates`：相似候選、分數（非機率）與理由，不自動合併。
- GET／POST `/api/garment-groups`，DELETE `/api/garment-groups/{id}`：確認及取消合併。
- 合併不改寫 item 的原始內容；以主 item 呈現群組，來源 item 可分別核對。

## 分工

整合者：app/store/schema/config、批次與分組交易、文件、最後驗證。
影像工作者：穿搭提示、選區媒體、pipeline、品質政策與相關測試。
介面工作者：多檔佇列、選人、批次進度、候選比較與來源切換、瀏覽器驗證。
相似度工作者：可重現本機特徵與候選排序、相關測試及交易獨立檢查。

## 驗收結果

功能實作與驗證完成：240 項單元／整合測試全通過；新增生活照瀏覽器 8 項、
舊流程 14 項、擴充情境 8 項，以及正式清單 5 項唯讀檢查均通過。
真人 SAM／Spark 的 4 案有 3 案符合事前內容預期，合照漏檢黑褲的失敗保留；
獨立 pants 提示成功補找。白衣輪廓不足造成的漏配已修正，原資料離線重算
找回兩對同照變體；仍不能據此宣稱不同拍攝條件下的辨識準確率。
