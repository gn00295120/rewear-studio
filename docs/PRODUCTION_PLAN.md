# 正式產品交付計畫

2026-10-22 使用者補充：「要完善到一個正式的產品」。此要求包含可驗證的核心效果與可靠交付，
不是將目前本機測試版改稱正式版。最新固定 100 張生活照的人工稽核同目標辨識為 90/100、可重建
來源 87/100、忠實完整重建 85/100。正確辨識目標中的重建為 85/90，但全部輸入端到端仍未達 90%。
一般照片準確率與自動核驗同款必須保持較窄、可驗證的宣稱。
最終本機／網站交付已完成 1,576 項程式回歸、隔離 wheel、實際資料不變重啟與 Linux arm64 HTTPS
容器 140 項檢查；尚未選定的公開網域及一般母體準確率不列為已驗收。

## 產品範圍與當前假設

使用者尚未選定對外網站或可安裝本機產品。已提出選擇，暫以網站型產品規劃帳號與個人衣櫃，
待回覆後調整交付方式；此假設不授權選用其他人的雲端專案、變更計費或發送帳號郵件。
現有本機模式及原始資料保持可用。公開服務必須另行明確設定，不能將既有無登入服務直接暴露。
第一版沿用繁體中文、台灣購買地區與手機／桌機網頁；收費、社群功能及原生手機 App 不屬於已確認需求。

## 多原照版進展

已將人工確認合併後的多原照接進實際重建：最多兩張額外原照、固定主照展示面、逐圖來源履歷、
跨工作取消、帳號隔離，以及刪除歷史來源後的備份還原。單件正面對照由徽記失真改善為可見錨點通過；
背面負向控制沒有混入胸前圖案。產品真實上傳與單次生成也保留圖案，仍保留自動 `needs_review`。
1,459 項完整程式測試及 39 個受影響瀏覽器情境通過；這些數字不計入 90% 保真分母。
新證據在 `out/verification/multiview-20261022/`，先前失敗控制與十件基準不覆寫。

前襟狀態改為獨立、可追溯且不可由補照覆寫的觀察；增加比較、預覽警告及候選選擇的一致性驗證。

`out/verification/primary-state-20261022/`，後續不得將此案例算作保真成功或再選擇性覆寫結果。

## 實作順序

1. 保留已凍結的來源與失敗案例，先驗證新的單原圖生成控制。能改善關鍵錯誤才擴大對照，
   不以大量無方向重試提高表面出圖率。真正改善必須能接入產品的可用服務，工具內單次成功不等於接入完成。
2. 補上網站模式的帳號與衣櫃隔離，先以獨立資料目錄驗證兩個帳號的完整操作及直接 URL 存取。
   後台工作與媒體需由同一個已驗證身分決定資料範圍，不能只在畫面隱藏他人資料。
3. 取得可用的原圖搜尋設定後，跑真實商品召回與頁面核對；保留空結果、失敗、相似款及同型號的不同結果。
4. 完成備份還原、升級復原、負載與失敗演練、手機／桌機完整操作，再在選定交付環境驗收。
5. 逐項對照本表及 `PRODUCT_READINESS.md`；任一核心要求未達成，持續標示為尚未完成，不能發布 90% 宣稱。
