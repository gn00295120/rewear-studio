# 使用同件衣服的其他照片

同件衣服在遠景、近拍或不同角度中，可能各自留下不同細節。先核對照片確實是同一件衣服，
再確認合併；詳情的「參考其他照片（選用）」可額外選最多兩張原照。現在開啟的衣物紀錄為主來源，
它決定展示正面或背面；其他照片不能把另一面的圖案移到展示面。

預設沒有選取其他照片。自動重建仍使用單照，確認合併本身不會觸發雲端生成。
選取後按生成才會將這些參考照片一起送至已設定的 Meta 模型。來源必須來自同一帳號、同一個人工
確認的群組，且仍有可用的原始圖片；AI 生成紀錄、重建圖及購買候選圖不接受為額外原照。
如果只拍到局部，請先核對衣物類別再確認，不能只為了送出而將不相關照片合併。

## 圖片與來源保存

每次生成會保存所選來源及圖片雜湊；已採用展示圖、完整預覽、未採用候選各有自己的來源履歷。
重試失敗或取消時，上一張圖保留原本的來源。生成中的選項會鎖定；如要更換，先取消或等它結束。

刪除任一參考紀錄／工作、取消合併或重新合併時，相關進行中生成會先取消。已完成的展示圖仍保留，
不存在的來源顯示「來源照片已移除」，不會用其他照片代替。備份與還原保留這份歷史紀錄，
也保留已完成圖；不會還原已經刪除的原照。現存工作若真的缺失圖片，備份仍會拒絕並要求處理。

## 保真限制與本次實測

多張參考不等於已確認同款、尺寸或隱藏構造。規劃、細節複核、生成及最後核對使用同一份來源；
模糊、遮住或相互矛盾的資訊仍保留未知。最多兩次生成及既有總時限不變。

2026-10-22 的控制測試使用同一件衣服的原始遠景、近景、商標近照與背面照。事前固定四個條件，
每個條件只生成一次；兩位獨立目視都確認：正面單照的徽記失真，多照保留雙橢圓與小勾；
背面兩個條件均維持素面。這是 **1 件衣服、2 個展示面**，不是四件獨立樣本。

產品實際流程另上傳三張原照，真實模型分析產生五筆結果；明確人工確認三筆是同件，近照並手動確認
衣物類別，再進行一次多照生成。可見正面錨點由兩位目視通過；自動核對仍因下擺局部參考範圍不足
保留 `needs_review`，完整圖以「AI 預覽・含推測」呈現。未把人工確認包裝成全自動辨識。

這個單例支持可選的多照功能，不能證明一般生活照已達 90%，也不能加入原固定十件的成功率分母。
原本單照保真與自動同款購買目標仍未達成。詳細請求、原照、失敗候選與兩份目視紀錄保存在
`out/verification/multiview-20261022/`，圖片僅作本機驗證，沒有加入安裝包或示範資料。

後續另測碎花洋裝與格紋襯衫。洋裝單／多照皆保留可見錨點；襯衫兩者都沒有保留主照前襟的展開程度，
多照控制另混入褲子抽繩。完整產品流程去除了旁件污染，卻仍未抓到前襟差異。
目前已增加主照狀態與候選獨立觀察的比較，但真實回歸仍被模型錯判為同樣敞開。
因此不能依賴「多照」或「模型核對」保證還原；原照、生成圖及目視失敗記錄都保留，仍需逐件核對。
新增證據在 `out/verification/multiview-heldout-20261022/` 與 `out/verification/primary-state-20261022/`。

## API

原本無 body 的 `POST /api/items/{item_id}/reconstruction` 保持單照行為。
多照可提供 `{"reference_item_ids":["其他來源紀錄ID"]}`，最多兩筆，不能包含本筆或重複值。
客戶端只能選紀錄 ID，不能提交檔案路徑或圖片網址。來源由伺服器所在帳號的資料庫解析。
相同選取的進行中請求沿用既有工作；不同選取回覆 409，避免默默忽略新選擇。

當次輸入儲存在 `reconstruction.reference_manifest`；各張圖片以自己的
`*_validation.plan.reference_manifest` 與 `*_reference_manifest` 保存履歷，不能回落到別次輸入。

新規劃的 `primary_front_state` 記錄主照前襟狀態、來源、證據與範圍；`candidate_front_state` 獨立記錄
候選觀察並綁定被選中的生成嘗試。這些是可追溯的模型觀察，不是物理真值。
兩個欄位都缺的舊報告保持原判準；僅一邊缺失時不能宣稱保留狀態。
